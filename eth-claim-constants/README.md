# eth-claim-constants

記事「OpenAI の ETH 反証主張に定数を入れると —— Dias と Lima の note を読み、数表を式から再計算した」（下書き）の数字を出したコード。

Dias と Lima の note（[arXiv:2611.00517v1](https://arxiv.org/abs/2611.00517v1)）の数表と定数を、式から再計算して、note が印字した桁で note の値と突き合わせる。
標準ライブラリだけで動き、乱数は seed（2611）を固定してある。1件でも食い違えば終了コードは 1 になる。

| ファイル | 中身 |
|---|---|
| `reproduce.py` | 再計算の本体。32項目を検査し、再計算した値と、比べる値（note の印字値。そうでないものは「期待」と表示）を並べて出す |
| `expected-output.txt` | 手元で出した出力（`規模` の行の時間と大きさだけは環境で変わる） |

## 再現

```bash
python3 reproduce.py
```

Python 3.15.2 で1.4秒ほどで終わる。最後に `すべて一致` と出れば、32項目がすべて通っている。内訳は、note の印字値との比較が26項目（表1の14、命題4.1と E5 の定数7、E5 の比3、命題 B.2 の2）で、残る6項目は preprint の (D.5)（3項目）、note の3変数の例（2項目）、乱数の式での補間の確認（1項目）だ。macOS 付属の Python 3.9.6 でも、`規模` の行以外は同じ出力になった。

## 検査していること

- note の表1の13個の値と、C=1 の一般の列に根がないこと（二分法）
- 命題4.1の定数 `K0`、密度4.26の係数、`(2·K0)²`、閾値 `log2 n`、`2^(C·n/√ln n)` 形の `C`
- 実験 E5 の3つの比（組の個数の対数と、見積もり `2π√(pN/6)` の比）。note に値のない `(N,p)=(6,1200)` も参考に出す
- 命題 B.2 の2つの交点（自然対数で 10^2390.2、底2で 2^65536）
- OpenAI の preprint の (D.5) `λ^(4/5) ≤ ⌊λ/2^17⌋` が `λ ≥ 2^85` でなければ成り立たないこと（整数の計算）
- note の第3.6節の3変数の例（`H(T) = 5 - 2T`）と、乱数の 3-CNF 30個で補間が全割り当ての数え上げに一致すること（note の実験 E1 と同じ形だが、生成器はこのスクリプトのもの）

## 検査していないこと

- どちらの論文の定理の正しさ。この検査は「note の式から、note の数字が出る」ことだけを見る
- note の実験 E2〜E4（経路の下限・SATLIB の木幅・変数消去との比較）
- note が定数を取り出した導出が、preprint の証明を正しく写していること。補題 D.5・式 (D.13)〜(D.15)・D.4.6〜D.4.7 節との突き合わせは、コードではなく手で行った

## 数字の再現について

- 乱数は seed（2611）を固定してあるので、`expected-output.txt` と同じ数字が出る
- 環境で変わるのは、`規模` の行の「オブジェクトの大きさ」と「作成にかかった時間」だけ。`bit_length`（1,033,927,232）と10進の桁数は環境によらない。大きさは CPython（64bit）で `sys.getsizeof` が返した値
- 閾値 `(2·K0)²` ビットの整数 `1 << 1_033_927_231` は、手元の Python では作れた。作れないのは、それだけ多くの変数が現れる入力のほうである
